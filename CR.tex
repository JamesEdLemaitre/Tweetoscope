\section{Secrets and Git}

When developping applications involving the access to a distant service using a private API key or credentials, it is crucial to not leak them in a public repository for example. 

It can be particularly tricky since even deleting the credentials in later versions of the code will not avoid other people to checkout older commits and read these tokens. 

Hackers might use these tokens for different reasons, including accessing a private API which cannot be accessed by them (some API access can be linked to an account and thus access private data. It can be the case for example with the Spotify API which allows you to access your private data through your API key), stealing paid credits, abusing the access until the key gets banned for too many requests for example.

Instead of writing the tokens inside of the code as a variable, it is a better practice to write them in a config.properties file and add this file to the .gitignore. 

For professional projects, specialized tools like Azure Key Vault can be used. 

Other tools can allow developpers to scan the changes before comitting automatically, or to scan a repository to check if secrets are included within the code.

\section{Risk Analysis / Initial Risk Analysis}

\underline{Impact of failure for Tweet Producer}:

New tweets are not received anymore by the application

There won't be a crash, and restoring this element will result in the application working again normally.

\underline{Impact of failure for Tweet Filter}:

Raw tweets are not filtered and transmitted to the next components. Messages will accumulate in the raw-tweets topic. Restoring this element will result in the filtering of all raw tweets without any loss of information.

\underline{Impact of failure for Hashtag Extractor}:

Hashtags are not extracted anymore from the tweets. Filtered tweets will accumulate in the filtered-tweets topic. Restoring this element will result in the extraction of the filtered tweets hashtags without any loss of information.

\underline{Impact of failure for Hashtag Counter}:

Hashtags are not counted anymore. Without any additional measure, restoring this element may result in errors in the results: the memory of the amount of past appearance of each hashtags will be lost and reset to $0$. 

\underline{Impact of failure for Visualizor}:

It is not possible to see the results anymore. Restoring this element will allow to show the results again, without any error in the data shown. 

\underline{Impact of failure of a Broker}:

Failure of a broker will not be a problem if it is replicated. 


\section{Task 9}

\subsection{Compilation}

Tous les composants Kafka ont été implémentés en Java et compilés avec Maven. La compilation s'effectue avec la commande suivante :

mvn -f ./pom.xml clean package

Note importante : La structure du pom.xml a dû être modifiée pour être correcte pour éviter des erreurs de compilation et des dépendances manquantes. C'est cette commande qui crée tous les .jar qui seront exécutés dans le terminal pour lancer les services Kafka. 

Les fichiers .jar sont créés sous :

target/<Nom du service>-jar-with-dependencies.jar

Par exemple, pour le producer des raw-tweets:

java -jar target/KafkaTweetProducer-jar-with-dependencies.jar

\subsection{Serveur Kafka}

Avant de lancer les composants, le serveur Kafka doit être démarré :

Génération d'un UUID pour le cluster:

% KAFKA_CLUSTER_ID="$($KAFKA_HOME/bin/kafka-storage.sh random-uuid)"

Formatage du storage :

%$KAFKA_HOME/bin/kafka-storage.sh format --standalone -t $KAFKA_CLUSTER_ID -c $KAFKA_HOME/config/server.properties

Démarrage du serveur Kafka :

% $KAFKA_HOME/bin/kafka-server-start.sh $KAFKA_HOME/config/server.properties


\subsection{Création des topics}

Les topics nécessaires doivent être créés avant le lancement des composants :

Topic pour les tweets bruts:

% $KAFKA_HOME/bin/kafka-topics.sh --create --bootstrap-server localhost:9092 --replication-factor 1 --partitions 1 --topic raw-tweets

Topic pour les tweets filtrés:

% $KAFKA_HOME/bin/kafka-topics.sh --create --bootstrap-server localhost:9092 --replication-factor 1 --partitions 1 --topic filtered-tweets

Topic pour les hashtags extraits:

% $KAFKA_HOME/bin/kafka-topics.sh --create --bootstrap-server localhost:9092 --replication-factor 1 --partitions 1 --topic hashtags

Topic pour le leaderboard

% $KAFKA_HOME/bin/kafka-topics.sh --create --bootstrap-server localhost:9092 --replication-factor 1 --partitions 1 --topic leaderboard

\subsection{Lancement des composants}

\textbf{KafkaTweetProducer}

Commande:

java -jar target/KafkaTweetProducer-jar-with-dependencies.jar [random|recorded]

Options:

\begin{enumerate}
\item random: implémente le producer random présent dans la version initiale du projet. 

\item recorded: implémente le producer lisant un fichier contenant des tweets au format .json.

Pour l'utiliser, il faut bien penser à créer une variable d'environnement précisant où se trouve le fichier source:

export tweetoscope\_sourcefile="..."

Contrairement au random, il ne fonctionne pas indéfiniment. Il ne lit qu'une seule fois le contenu du fichier puis s'arrête. 
 
\end{enumerate}

\textbf{KafkaTweetFilter}

Ce composant consomme les tweets du topic raw-tweets, les filtre et publie les tweets filtrés dans filtered-tweets :

java -jar target/KafkaTweetFilter-jar-with-dependencies.jar [option] [paramètre]

Note d'implémentation : La classe RecentTweetFilter a été réimplémentée sans utiliser le pattern .subscribe(). Cette approche diffère du code initial mais respecte le modèle consumer-producer de Kafka.

Options:

\begin{enumerate}
\item recent 

Comportement : Ne conserve que les tweets créés il y a moins de 24 heures.

Critère : Compare la date de création du tweet (createdAt) avec l'heure actuelle.

\item lang [codelangue] 

Comportement : Ne conserve que les tweets dans la langue spécifiée. Si aucun code de langue n'est fourni, "en" (anglais) est utilisé par défaut.

Critère : Compare le champ lang du tweet avec le code langue fourni.

\item empty

Comportement : Ne filtre que les tweets ayant un contenu textuel non vide (après suppression des espaces).

\end{enumerate}

\textbf{KafkaHashtagExtractor}

Ce composant consomme les tweets filtrés et extrait les hashtags :

java -jar target/KafkaHashtagsExtractor-jar-with-dependencies.jar

\textbf{KafkaHashtagCounter}

Ce composant compte les occurrences de chaque hashtag et publie les résultats dans le topic leaderboard :
java -jar target/KafkaHashtagCounter-jar-with-dependencies.jar

\textbf{Leaderboard}

Ce composant consomme le topic leaderboard et affiche les résultats :

java -jar target/KafkaLeaderboard-jar-with-dependencies.jar
